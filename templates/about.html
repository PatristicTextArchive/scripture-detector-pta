What is Scripture Detector?

Scripture Detector is an AI-powered web application that analyzes historical and literary texts to find and classify all the ways biblical scripture appears within them. Given any piece of text, the application uses large language models to locate exact quotations, partial quotations, paraphrases, and allusions to specific Bible verses.

Each detected passage is linked to the exact verse(s) it references, displayed in context within the original document, and explored through interactive visualizations. The application is designed for scholars, students, and researchers working with texts that draw on the biblical tradition.

This version works with Greek texts (Septuagint and New Testament) and Latin texts (Vulgate), and reads and writes TEI XML: detected quotations are written back into the TEI file following the encoding guidelines of the Patristic Text Archive. It is a fork of the Scripture Detector by Dr. William J.B. Mattingly (Yale University).

How It Works

1

Add a Source Text or import TEI

Paste any Greek or Latin text — a sermon, a letter, a chronicle, a theological treatise — into the Sources page, or import one or more TEI files. For TEI the language is read from xml:lang of the first <div> in <text> (grc or lat); the running text is extracted and the original XML is kept. Everything is stored locally in a SQLite database.

2

AI Detection via Google Gemini

Click "Process with AI" to send the text to Google Gemini with a carefully engineered prompt. The prompt names the Bible corpus of the text's language and lists typical introductory formulas (such as γέγραπται, φησίν, λέγει; scriptum est, ait, inquit). Passages already marked as <quote> in a TEI file are passed on as hints. The model returns a structured JSON list of all detected scriptural passages, their verse references, and classification types. Long texts are analyzed in chunks.

3

Span Location & Annotation

The app finds the exact character span of each detected quote within the original text — ignoring accents, breathings, case, and sigma variants — and checks every reference against the verse database; invented verses are dropped. Each quote gets a match score: the share of its words found in the referenced verse(s).

4

Interactive Exploration

View color-coded highlights directly in the text, click any passage to see the verse references and original Bible text side-by-side, edit or add annotations manually, and explore distribution charts by Bible book, testament, and quote type.

5

Export TEI

Export the result as TEI following the PTA guidelines: written into the original file for imported TEI, or into a minimal PTA-style document for pasted text. Notes on anything that could not be encoded are listed with the passage, its context, and its location in the file.

Quote Classification Types

The AI classifies each detected passage into one of four categories:

Full

A complete or near-complete verse quoted verbatim from the Bible.

Partial

A recognizable portion of a verse, quoted with minor variation or truncation.

Paraphrase

Biblical content clearly restated in different words while preserving the meaning.

Allusion

A brief phrase, thematic echo, or indirect reference to a specific verse.

Bible Texts & the Patristic Text Archive

The Greek Bible texts come from the Patristic Text Archive (PTA), a digital archive of patristic and related texts at the Berlin-Brandenburg Academy of Sciences and Humanities. They are taken from the PTA data repository on GitHub, PatristicTextArchive/pta_data (data/pta9999, Greek editions grc1): the Septuagint in Rahlfs' numbering and the Greek New Testament — 80 books and 37,034 verses.

  • The Greek texts are used under the licence stated in the PTA files, CC BY-SA 4.0; the derived verse database in data/greek is shared under the same licence. How to cite the PTA data is described in the CITATION.cff of the repository.
  • Book codes follow the PTA abbreviations (Gn, Ps, Mt, …), so that references can be exported as LXX:Ps:62:9 or NA:Mt:5:9. For Latin texts the prefix is Vg (Vg:Gn:1:1).
  • Only the primary text form (grc1) of each book is used; alternative forms (e.g. Judges B, Old Greek Daniel) are not included.
  • The Latin Vulgate verse database was part of the original Scripture Detector.
  • To rebuild the Greek data: python scripts/build_greek_bible.py --pta-data /path/to/pta_data

TEI Import & Export

Results are encoded as described in the PTA encoding guidelines for biblical quotations and allusions: 

<quote type="marked">ἐκολλήθη ἡ ψυχή μου ὀπίσω σου<ref decls="#biblical" cRef="LXX:Ps:62:9"/></quote>
<seg type="allusion">…<ref decls="#biblical" cRef="NA:Phil:2:8-10"/></seg>
  • Full and partial quotations become <quote> (marked if introduced by a formula, otherwise unmarked), paraphrases <quote type="paraphrasis">, allusions <seg type="allusion">.
  • Consecutive verses become one reference with a range (2:8-10); verses that do not follow each other are joined with a dot (2:8.10).
  • Quotations crossing element boundaries (<hi>, <lb/>, <pb/>, paragraphs) are split and linked with @prev / @next.
  • Existing <quote> elements are never duplicated: they only receive the <ref> and, if missing, a @type. Quotes that already carry a biblical reference stay untouched.
  • The header receives the refsDecl for #biblical, the annotation-status declarations, and a <change> entry; the status is declared as partially annotated — please review the automatic results.
  • Re-importing an exported file restores the annotations, and re-exporting replaces them instead of duplicating them.
  • In manuscript transcriptions the PTA does not use <quote>; the export warns in that case.

Technical Requirements

  • Python 3.10+ with Flask — the entire backend runs as a lightweight local web application.
  • SQLite — all sources, annotations, and settings are stored in a local database with no external server required.
  • Bible verse databases are included and used for verse lookup, reference validation, and match scores: the Greek Bible (Septuagint and New Testament, 37,034 verses, from the Patristic Text Archive) and the Latin Vulgate. lxml is used to read and write TEI.
  • Google Vertex AI or a Gemini API key from Google AI Studio — this is the only external dependency and is free to obtain.
🔑

Only a free Gemini API key is required. Get yours at aistudio.google.com/apikey and enter it in the Settings page to start using the app immediately. No cloud account, credit card, or additional setup is needed.

Advanced Search

The Sources page includes a powerful multi-layered search system that lets you find sources by their text content, the Bible books they reference, specific chapters, or individual verses — all updating in real time as you type.

Text Content

Full-text search across all source documents. Matching passages are highlighted in context with the search term shown inline.

Bible Book

Find all sources that contain any reference to a chosen Bible book, using a searchable dropdown of all books of the Greek and Latin corpora.

Chapter

Narrow results to sources referencing a specific chapter (e.g. Psalms 23) using cascading book → chapter selectors.

Verse

Pinpoint sources that reference a specific verse (e.g. John 3:16) using book → chapter → verse number selectors.

Stacked filters with AND / OR logic — click Advanced to open the filter builder and stack any number of filters. Toggle between AND (source must match all filters) and OR (source must match any filter). Active filters are summarized as removable chips below the search bar. Match evidence appears directly on each source card, showing the exact text snippet or the matched verse and quote.

Key Features

  • Full-text AI analysis using Google Gemini with structured JSON output, chunked for long texts.
  • Greek and Latin corpora (Septuagint, New Testament, Vulgate); the language of a TEI file is read from xml:lang.
  • TEI import and export following the PTA encoding guidelines (<quote>, <seg type="allusion">, <ref decls="#biblical" cRef="…"/>).
  • Existing <quote> elements are checked for biblical references and enriched instead of duplicated.
  • Accent-, breathing-, and case-insensitive matching; every reference is validated, and each quote gets a match score.
  • Export notes list the affected passage with context and location in the file.
  • Color-coded in-text annotations with click-to-explore interactivity.
  • Selection-based re-analysis: highlight any passage and re-run AI detection on just that section.
  • Manual annotation editor with a Bible verse picker (book → chapter → verse).
  • Advanced search with real-time filtering by text content, Bible book, chapter, or verse — stackable filters with AND / OR logic and inline match evidence.
  • Distribution charts showing which Bible books and testaments are most referenced.
  • Global analytics dashboard across all sources.
  • Support for both Gemini API (free tier) and Google Vertex AI.
  • Model switching — choose between available Gemini model versions.
  • Runs entirely locally — your texts never leave your machine except for the AI API call.
  • Open source: original project (Yale University) · Greek/Latin/TEI version based on it.
